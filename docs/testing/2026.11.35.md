## Finding: keys on 26.3

The first outline tours crashed the client (`IndexOutOfBounds` in `InputConstants.isKeyDown`, called from `KeyMapping.setAll`) as soon as a script key was registered, with default codes -1, 346 and 80. 26.3's `isKeyDown` reads the SDL keyboard state indexed by key value (`KEY_A = 4`, `KEY_G = 10`, `KEY_GRAVE = 53` in 26.3 against 65, 71 and 96 in 26.1.2 and 26.2), so a script's GLFW code was used as an SDL scancode: the wrong key at best. Fixed with `KeyCodes` (translation on registration and for the `keyPressed` event); the confirming launch registered a key and passed. I could not explain from the source alone why code 80 (a valid scancode) crashed before the fix; the launch after the fix is the evidence, not the explanation. The translation of `keyPressed` event codes is compile-checked and unit-tested, not seen in a real client.
