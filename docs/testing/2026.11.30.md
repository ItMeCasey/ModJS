# ModJS 2026.11.30 validation

Local candidate tested November 8, 2026. No tag, push, release or upload was performed.

All ten modules build with 87 passing shared unit tests each. Headless self-tests pass with
optional mods absent: 94 checks per 1.20.1 module, 91 on Forge 1.21.1/26.x and NeoForge 1.21.1,
and 92 per NeoForge 26.x module. The additional NeoForge check confirms the unification loot
modifier is present in the actual resource manager, including after removing obsolete list metadata.
Concise evidence: `selftest-<module>.log`; full local build logs are under ignored `release/`.

## Client coverage

Every module verifies client initialization, asset preload, login/logout, ticks, static and filtered
dynamic tooltips, HUD text and rectangles, raw loader input, native key registration, rebinding,
queued key presses, a chat packet received by the integrated server, and clean level unload.
Evidence: `client[-viewer]-<module>.log`; frames: `../frames/hud-<module>.png`.
The drivers call Minecraft/loader APIs inside the isolated game. Physical keyboard input was not
injected or tested. Tooltip callbacks use real item tooltip construction.

Runtime dimension persistence passed on every module across two clean client launches: create
`modjs:restart_probe`, teleport, place a diamond block, quit, relaunch, verify the restored level and
saved block. Evidence: `restart-<module>-1/2.log` and `restart-client-<module>-1/2.log`.

## Test-world setup

Copied worlds start in Peaceful with mob spawning disabled before Minecraft opens them.
Legacy gamerules also disable patrols, traders, phantoms, wardens and raids; modern gamerules
also disable monsters and spawner blocks. A fresh integrated player avoids inheriting a dead
player from an old screenshot fixture. These settings were checked against temporary copies
of all ten fixtures, and the three NeoForge 26.x worlds retained Peaceful and disabled spawning
after their actual REI runs and clean exits. Optional-mod gamerules are removed from modern
isolated fixtures so absent optional registries cannot make Minecraft discard the rule file.

## Reproduction and limits

- `python scripts/client_tour.py <module> [--jei|--emi|--rei]`: one client check.
- `python scripts/restart_tour.py <module>`: two-launch persistence check.
- `python scripts/verify_matrix.py <module> ...`: build, unit tests and headless self-test.
- The client tools use the hidden, muted `launch-isolated.ps1` desktop and preserve local
  scripts and optional mod jars. Opt-in viewer profiles are development dependencies only.
- NeoForge 1.20.1's NeoGradle 7 runtime uses Forge-remapped viewer jars and remaps their
  access-transformer rules for the development runtime; run all three Forge 1.20.1 viewer
  profiles first to populate those local cache artifacts. Its build checks source parity with Forge.
- Rhino 1.7.15's interpreted block `const` behavior is unreliable in loops; the drivers use `let`
  for loop locals. This engine limitation is documented in the scripting reference.
- Forge 1.21.1's existing development-client command/reload-hook and first-title-screen issues
  remain documented in `../PORTING.md`. This work does not establish behavior in a production launcher.
- Jade 1.20.1 remains compile-checked; its existing development mixin naming issue is separate
  from these viewer profiles. Custom tool models and worn armor textures were not visually verified.
- No separate dedicated server with a remote client was tested. Existing BEI reflection integration
  was not changed; viewer grouping remains outside these native JEI/EMI/REI adapters.
